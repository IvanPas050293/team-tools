# improve-promptness — улучшение промпта

Превращает сырой текст запроса в качественный структурированный промпт и доводит его до выполнения. Главная ценность — асинхронный диалог через файл: вопросы записываются в `Answer the questions.md`, пользователь отвечает прямо в нём, а после чтения ответов файл удаляется.

## Вход

Пользователь даёт сырой текст (аргументом или в предыдущем сообщении). Если текста нет — попросить прислать его перед началом работы.

## Процесс

### Шаг 1. Оценка по пяти признакам

Оценить сырой текст по пяти признакам. Для каждого — оценка и одна строка обоснования:

- **Ясность** — понятно ли, о чём речь, без догадок.
- **Конкретность** — есть ли детали: объекты, действия, условия, числа.
- **Контекст** — известно ли, где это применяется, для кого, на чём.
- **Полнота** — хватает ли данных, чтобы выполнить без дофантазирования.
- **Формат** — задан ли вид результата (структура, длина, вид).

Оценки: ✓ хорошо / ◐ частично / ✗ отсутствует.

### Шаг 2. Уточняющие вопросы — в файл

Там, где оценка ◐ или ✗, — записать уточняющие вопросы в файл `Answer the questions.md`, чтобы пользователь ответил прямо в нём. Правила:

- Создать файл через Write в корне проекта, полный абсолютный путь (например `C:\Users\Ivan\Проекты\lesson\Answer the questions.md`).
- Структура файла: заголовок + блок из 2–4 конкретных вопросов по приоритету (недостающий контекст → конкретика задачи → ограничения → формат ответа). Под каждым вопросом — пустая строка для ответа пользователя.
- Вопросы по делу, не «расскажи подробнее вообще».
- Сообщить пользователю в чате: «Вопросы записаны в файл Answer the questions.md — ответьте в нём же.»
- Если новых пробелов нет — файл не создавать, перейти к шагу 4.

### Шаг 3. Прочитать ответы и удалить файл

Когда пользователь сообщил, что ответил:

1. Прочитать `Answer the questions.md` (полный абсолютный путь).
2. Учесть ответы: переоценить признаки.
3. Удалить файл — он больше не нужен.
4. Продолжить с шага 4.

### Шаг 4. Итоговый промпт

Собрать итоговый промпт из пяти секций с учётом ответов:

1. **Роль** — от чьего лица выполняется: экспертность, должность, перспектива («ты — старший Python-разработчик»).
2. **Контекст** — предыстория, окружение, аудитория: что уже известно, где применяется, для кого делается.
3. **Задача** — конкретное действие и объект: что сделать и с чем.
4. **Ограничения** — запреты, стек/технологии, объём, сроки, стиль.
5. **Формат ответа** — как оформить результат: структура, длина, вид (список/код/таблица/текст).

Каждая секция конкретная и однозначная, без «не знаю» и общих фраз. Оформить итог в fenced code-блок, чтобы легко копировался как есть.

### Шаг 5. Before/After (обязателен)

Показать пользователю скилла, что именно изменилось. Для каждой секции строка «было → стало» с типом изменения:

- ➕ добавлено — в исходнике секции не было
- ✏️ уточнено — деталь появилась из ответов пользователя
- 🔁 переформулировано — текст переписан без изменения смысла
- ✔️ без изменений

Если в исходнике секции не было — показать «— → добавлено: …». В конце — короткая сводка: сколько секций добавлено, уточнено, без изменений.

### Шаг 6. Подтверждение diff и выполнение

1. Показать before/after (diff) пользователю.
2. Дождаться подтверждения пользователя.
3. После подтверждения — выполнить улучшенный промпт как реальную задачу: сделать то, что в нём предписано, с учётом роли, ограничений и формата ответа. Не ограничиваться выдачей текста промпта.

## Выход (порядок вывода)

1. Оценка по пяти признакам (кратко, с обоснованием).
2. Файл `Answer the questions.md` с уточняющими вопросами.
3. Прочитать ответы из файла, удалить файл.
4. Итоговый промпт в code-блоке.
5. Before/After по секциям.
6. После подтверждения — выполнить улучшенный промпт.

## Пример

Вход: «этот метод не работает»

1. **Оценка:**
   - Ясность: ◐ — непонятно, какой метод и что значит «не работает».
   - Конкретность: ✗ — нет ни объекта, ни симптома.
   - Контекст: ✗ — неизвестен код/стек/окружение.
   - Полнота: ✗ — выполнить нельзя.
   - Формат: ✗ — не задан.

2. **Файл `Answer the questions.md`:** записать вопросы: «Какой метод/функция и где он находится?», «Что происходит: ошибка, неверный результат, падение?», «Какой стек и версии?», «Что должно получиться в идеале?». Сообщить пользователю, что нужно ответить в файле.

3. **После ответов:** прочитать файл, учесть ответы, удалить файл.

4. **Итоговый промпт:** code-блок с пятью секциями.

5. **Before/After:** строки по каждой секции.

6. **Выполнение:** после подтверждения diff — выполнить улучшенный промпт как задачу.
